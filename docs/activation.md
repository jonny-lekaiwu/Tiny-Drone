# 实名登记激活

本工程已接入 `D:\device-activator` 的 USB 激活协议，无需先刷临时的
`Tiny-Drone-Register` 固件。当前网页支持 ESP32-S3。

## 编译

在已加载 ESP-IDF 5.5 环境的终端中，进入本工程后运行 `idf.py build`。
新工程的默认目标为 `esp32s3`，产物为 `build/Tiny-Drone.bin`。
若已有 `sdkconfig` 选成了 `esp32`，先执行 `idf.py set-target esp32s3`。
工程只接受 `esp32s3` / `esp32c3`，会在配置阶段拒绝不匹配的芯片目标。

激活组件显式依赖 `vfs`；USB 控制台启用时才接入其 VFS 驱动。
无需修改 ESP-IDF 安装目录中的组件。移动工程目录后，旧 CMake 缓存或指向旧目录的
`build` 联接不可继续使用，应在新位置重新生成构建目录。

## 使用流程

1. 烧录本工程固件。未激活时仍可连接 Wi-Fi、配置和使用已有通信功能，
   但不能解锁飞行，普通推力和电机自检被锁定。拉油门时播放三声短促的未激活提示音。
2. 用 Chrome 或 Edge 打开激活网页，连接芯片原生 USB Serial/JTAG 对应的 COM 口。
   关闭占用该端口的串口监视器。`AT+HELLO` 会返回本机产品序列号和激活状态。
3. 使用与本机序列号一致的实名登记二维码。网页查询 UOM，登记状态为“正常”后
   发送激活命令；二维码属于其他设备时，固件拒绝写入。
4. 固件保存记录、返回成功并重启。重启之前电机始终锁定；重启加载有效记录后
   恢复原有飞行流程。重新连接网页可读回已激活状态。

产品序列号沿用原 RID 算法：`DY00TD00` + 芯片出厂 MAC 的 12 位大写十六进制，
总长 20 位。激活不能改写本机产品序列号。RID 默认启用，使用同一个产品序列号，
登记号使用保存的 `UASxxxxxxxx` 后八位；未激活时登记号字段为零。

## 电机锁定开关

在 `components/config/include/config.h` 修改唯一的激活策略开关并重新编译：

```c
#define ENABLE_ACTIVATION_MOTOR_LOCK 1
```

- `1`（默认）：未激活不能解锁或输出飞行推力；拉油门时默认提示，无独立提示音开关。
- `0`：取消激活对解锁、电机输出及自检的限制，也不播放未激活提示。
  原有低电量、倾倒等保护保持不变。USB 激活、NVS 保存、真实激活状态和 RID 登记号
  仍正常工作，不会把未激活设备伪装成已激活。

默认提示为三声短音，每声 70 ms、间隔 70 ms，使用现有电机发声方式的 5% 占空比。
普通模式油门达到最小有效推力时触发；定高/定点模式需向上推过中位死区，
中位不会触发。持续保持油门只响一组，回到低位（辅助模式回到中位死区或以下）
再推才会再次提示，两组至少间隔两秒。控制数据超过 500 ms 未更新时丢弃待播放提示。
提示结束后归零输出并恢复 PWM 频率；发声期间普通推力仍被锁定。

开关为 `0` 时，USB 激活成功只保存记录，不自动重启，以免打断可能正在运行的设备；
需手动重启后加载新的激活状态。默认 `1` 时仍自动重启。

## USB 协议

命令以 CR 或 LF 结束，兼容 CRLF：

```text
AT+HELLO
+HELLO:ESP32-S3|usb_serial_jtag|Tiny-Drone-activation-1|0|DY00TD00xxxxxxxxxxxx|-

AT+ACTIVATE=<UUIDv4>|<本机20位产品序列号>|<UAS加8位大写字母或数字>|正常
+ACTIVATE:<产品序列号>|<完整登记标志>|正常
OK
```

启动时输出 `+STATUS:NOT_ACTIVATED` 或
`+STATUS:ACTIVATED|<产品序列号>|<完整登记标志>`。
拒绝请求时返回 `ERROR:<原因>`。重复发送相同的已激活记录会返回成功，
但不写入、不重启；已激活设备不允许通过此命令覆盖凭证或登记号。
过户、注销和重新绑定尚无专用流程。

## 保存及升级

激活记录作为一个带版本号的 NVS blob，保存在 `uom/record`，避免多字段分次写入
产生混合记录。启动校验 UUID、产品序列号与本机一致、登记号格式和版本。
也支持临时工程的 `uom/activated`、`cert_id`、`upic_msn`、`uas_code` 旧记录，
但必须完整且属于本机。记录损坏或不匹配时保持未激活。

保留 NVS 的应用升级会保留激活。整片擦除、覆盖 NVS 分区，或 NVS 初始化失败时
原工程执行的自动擦除，会清除激活；启用电机锁定开关时会重新锁定电机。
请不要把含其他设备激活信息的 NVS 镜像用于批量烧录。

## 信任边界

沿用现有方案：UOM 查询由电脑网页完成，固件校验网页送来的字段并绑定本机，
不直接联网查询 UOM，也没有校验服务端数字签名。
因此这实现的是正常用户流程的激活与电机锁定，不能阻止直接构造 USB 命令
或修改固件的用户绕过登记。需要防伪造的授权时，须另加服务端签名及设备验签。

## 验证

运行 `python scripts/test_activation.py`（需 GCC）。测试执行真实 C 代码，
以模拟 NVS/USB/电机硬件验证：序列号绑定、非法参数、超长/含 NUL 命令、
写入或提交失败、激活后重启前保持锁定、重复激活、损坏/旧记录、
解锁及强制解锁拦截、普通推力/电机自检/普通提示音输出拦截、RID 数据包中的身份字段。
同时测试宏的 `1`/`0` 两种取值、油门边沿与辅助模式死区、提示节流及过期、
三声固定提示的占空比与停止输出、提示期间普通推力仍被拦截。

上板验收需拆除桨叶：分别检查空 NVS 时的连接配置和电机锁定、错误二维码拒绝、
未激活拉油门提示及持续保持时不重复播放、正确二维码激活、断电重启保持激活，
并用 RID 接收端核对本机序列号及登记号。提示音的实际响度仍需在电机上确认。
主机测试和编译不能替代 USB、实际电机和无线广播的实机验证。
